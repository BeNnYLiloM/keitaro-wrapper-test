# Keitaro wrapper

Обёртка над Admin API рекламного трекера Keitaro (учебный стенд `keitaro-for-tests.etolegko.com`).

1. **Создаватор кампаний.** Принимает название, гео (одну или несколько стран) и оффер, а создаёт кампанию
   с доменом, группой и источником и двумя потоками:
   - **Поток 1** — посетители из указанных стран → редирект на `https://google.com`;
   - **Поток 2** — все остальные → выбранный оффер (100%).
2. **Редактор кампании.** Изменения копятся в черновике и уходят в Keitaro по кнопке «Опубликовать»:
   - «Добавить» — оффер появляется в списке с пометкой «новый»;
   - «Удалить» — оффер помечается «будет удалён» и зачёркивается;
   - удалённые офферы **не пропадают**: после публикации они остаются в разделе «Удалённые офферы»
     с кнопкой «Восстановить» — вернуть оффер можно в любой момент;
   - карточка потока подсвечивается, появляется панель «Опубликовать / Отменить».

   Доли пересчитываются **поровну**, целыми числами с суммой 100%: 2 оффера → 50/50, 3 → 34/33/33.
   Кнопка 📌 закрепляет текущую долю оффера (сохраняется **сразу**, без публикации): при следующих
   добавлениях и удалениях она не меняется, остальные офферы делят остаток поровну.

**Стек:** FastAPI · SQLAlchemy 2.0 (async) · Alembic · PostgreSQL · httpx · React + TypeScript (Vite) · Docker Compose.

---

## Быстрый старт (Docker)

Нужен только Docker (Docker Desktop на Windows/macOS).

```bash
cp .env.example .env          # затем вписать KEITARO_API_KEY
docker compose up --build
```

Откройте http://localhost:8000. Документация API (Swagger) — http://localhost:8000/docs.

Ключ берётся на стенде по кнопке «API ключ» вверху страницы.

При старте контейнер `app` сам выполняет `alembic upgrade head`, затем запускает uvicorn.
Postgres снаружи доступен на порту `5433` (`keitaro` / `keitaro`, база `keitaro`).

### Тесты

```bash
docker compose run --rm --no-deps app pytest -q
```

Тестам не нужны ни Postgres, ни стенд: Keitaro подменяется фейком на `respx`, база — SQLite в памяти.

## Миграции

Миграции лежат в [backend/alembic/versions](backend/alembic/versions). URL базы Alembic берёт из настроек приложения
(`DATABASE_URL`), поэтому отдельно его прописывать не нужно.

```bash
# применить все миграции (в Docker это делается автоматически при старте)
docker compose exec app alembic upgrade head

# после изменения моделей в backend/app/models.py — сгенерировать новую миграцию
docker compose exec app alembic revision --autogenerate -m "описание"

# откатить последнюю миграцию / посмотреть текущую версию
docker compose exec app alembic downgrade -1
docker compose exec app alembic current
```

> Код внутрь контейнера копируется при сборке. Чтобы новая миграция попала в репозиторий,
> генерируйте её при локальном запуске (см. ниже) или скопируйте из контейнера через `docker compose cp`.

## Запуск без Docker (для разработки)

Нужны Python 3.12+, Node 20+ и Postgres. Postgres можно взять из compose: `docker compose up -d db`.

```bash
# backend
cd backend
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
cp ../.env.example .env              # вписать KEITARO_API_KEY и раскомментировать DATABASE_URL
alembic upgrade head
uvicorn app.main:app --reload        # http://localhost:8000
pytest -q

# frontend (в другом терминале)
cd frontend
npm install
npm run dev                          # http://localhost:5173, /api проксируется на :8000
```

## Как это устроено

```
Браузер (React) ──► FastAPI (/api/*) ──► Keitaro Admin API
                         │
                         └──► PostgreSQL (SQLAlchemy)
```

Браузер не ходит в Keitaro напрямую: API-ключ остаётся на сервере.

### Структура

```
backend/
  app/
    main.py              приложение, обработчики ошибок, раздача собранного фронта
    config.py            настройки (pydantic-settings)
    models.py            таблицы SQLAlchemy
    schemas.py           схемы запросов и ответов API
    keitaro/client.py    асинхронный клиент Keitaro (httpx) + KeitaroError
    services/
      campaigns.py       создание (с откатом), просмотр, список, удаление
      editor.py          публикация черновика офферов, пины
      pins.py            закреплённые доли (таблица pinned_offers)
      archive.py         корзина удалённых офферов (таблица removed_offers)
      shares.py          формула долей с учётом закреплённых
      offers.py          кэш каталога офферов для автокомплита
      references.py      домены, группы, источники (кэш в памяти)
      countries.py       коды стран и нормализация гео
    api/                 роуты FastAPI
  alembic/               миграции
  tests/                 pytest: фейковый стенд на respx + SQLite в памяти
frontend/src/
  pages/                 «Новая кампания», «Кампании», «Редактор»
  components/            редактор офферов с черновиком, автокомплит, ввод стран, тосты
```

### Что хранится в БД

Кампании, потоки и доли хранятся в Keitaro, обёртка их не дублирует. В своей базе она держит:

| Таблица | Зачем |
|---|---|
| `campaigns` | реестр кампаний, созданных через обёртку: гео, исходный оффер, id обоих потоков |
| `offers_cache` | копия каталога офферов: автокомплит ищет по ней и не дёргает Keitaro на каждую букву |
| `pinned_offers` | закреплённые доли: какие офферы в каком потоке закреплены |
| `removed_offers` | корзина: удалённые из потока офферы (доля и статус на момент удаления) для «Восстановить» |
| `operations_log` | история операций: что сделали, состав офферов до и после, ошибки |

### Создание кампании

1. Валидация: страны есть в ISO 3166-1 (регистр и дубли нормализуются), оффер существует.
2. `POST /campaigns` — имя, `domain_id`, `group_id`, `traffic_source_id`, ротация по позиции, CPC.
3. `POST /streams` — поток 1: `schema: redirect`, `action_payload: https://google.com`,
   фильтр `country` / `accept` / `[страны]`.
4. `POST /streams` — поток 2: `schema: landings`, `offers: [{offer_id, share: 100}]`.
5. Если поток не создался, кампания удаляется из Keitaro, чтобы на стенде не оставалась полусобранная кампания.
   Ошибка уходит пользователю и в журнал операций.

### Редактор офферов

**Черновик.** Добавление, удаление и восстановление офферов происходят только в браузере. Строки помечаются
(«новый» — зелёным, «будет удалён» — красным и зачёркнуто), рядом с долей видно «было → станет».
По «Опубликовать» уходит один запрос с итоговым списком:

```
PUT /api/streams/{id}/offers
{"offers": [{"offer_id": 18002}, {"offer_id": 18005}], "base": [{"offer_id": 18002, "share": 50}, ...]}
```

Сервер:
1. сверяет `base` (с чего начиналось редактирование) с текущим потоком в Keitaro: если поток успели
   изменить, отвечает 409, чтобы не затереть чужие правки;
2. считает доли ([shares.py](backend/app/services/shares.py)): закреплённые офферы сохраняют текущую долю,
   остальные делят остаток поровну (`остаток // n`, остаток от деления по +1 первым);
3. записывает список через `PUT /streams/{id}` (поле `offers` заменяет состав целиком) и перечитывает поток,
   поэтому интерфейс показывает ровно то, что сохранил Keitaro.

**Корзина и «Восстановить».** Keitaro удаляет оффер из потока безвозвратно, поэтому при публикации
удаления обёртка кладёт оффер в таблицу `removed_offers`: долю на момент удаления, статус и время.
В редакторе такие офферы показываются в разделе «Удалённые офферы» под списком, у каждого есть кнопка
«Восстановить». Восстановление тоже идёт через черновик: оффер появляется в списке с пометкой
«будет восстановлен», а после «Опубликовать» возвращается в Keitaro с прежним статусом
(`active`/`disabled`). Доли при этом пересчитываются поровну, как для нового оффера, и запись из корзины
удаляется. Если оффер вернули в поток прямо в Keitaro, из корзины он скрывается.

**Пин.** `PUT` / `DELETE /api/streams/{id}/offers/{offer_id}/pin` применяются сразу. Закрепление хранится
в нашей таблице `pinned_offers` (в Keitaro такого поля нет), доли в Keitaro при этом не меняются.
Закрепить можно только опубликованный оффер. Когда закреплённый оффер удаляют, закрепление снимается.

Примеры: `[📌50, -, -]` → 50/25/25; `[📌40, -, -, -]` → 40/20/20/20.
Публикация отклоняется с понятной ошибкой, если:
- все офферы закреплены, а их сумма не 100%;
- незакреплённым не хватает хотя бы по 1%;
- в потоке не осталось ни одного оффера.

Интерфейс считает те же доли заранее и показывает ошибку до публикации.

Ещё несколько правил:
- Порядок офферов и их `state` сохраняются.
- Операции над одним потоком выполняются по очереди (asyncio-лок).
- Все публикации и пины пишутся в журнал `operations_log`, история показывается внизу страницы кампании.

### Ошибки Keitaro

| Ответ стенда | Ответ обёртки |
|---|---|
| 401/403 | 502 «Keitaro отклонил API-ключ» |
| 404 | 404 |
| 400/409/422 | 422 + текст ошибки Keitaro |
| 5xx / недоступен | 502 |
